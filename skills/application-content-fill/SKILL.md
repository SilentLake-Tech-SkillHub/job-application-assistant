# 投递内容填写

默认从用户指定的投递简历中取内容；用户有额外要求时，按要求选择材料和填写方式。由Agent读取、映射、填写、上传和读回，用户审核最终投递内容。

## 确认材料与事实来源

1. 从项目Router及私有投递配置定位用户指定的简历，核对语言、版本、成品状态、文件内容和Hash。确认附件文件与表单来源；材料已经明确时直接读取，不重复询问简历里已有事实。
2. 优先级为：用户明确更正或额外要求 → 用户指定的投递简历 → 用户明确允许补充的其他材料。未获补充要求时，不能自行改用旧简历、历史申请、网站解析结果、项目仓库或其他已验收版本。
3. 用户要求按空间采用长版/压缩版时，从指定且已验收的版本补充对应项目；逐条保留来源和版本。不同版本的数值或状态冲突时，以用户最新明确确认的事实为准；仍有具体冲突只确认该项。
4. 建立私有字段映射：表单字段/所属条目、拟填完整内容、简历段落或用户回复、版本、缺失项、控件限制和读回结果。个人信息及简历原文只保存在私有项目，不能进入公开Skill、测试样例或Issue。

## 先上传，再校正自动解析

- 检查上传是否触发自动解析。需要替换附件时，先上传正确简历并等解析完成，再进行手工填写；防止后上传把已校正内容覆盖。
- 精确定位当前可见上传按钮，检查已经打开的系统文件选择框，再选择一次目标文件。读回网站显示的文件名及上传成功状态。
- 把解析结果作为待核对草稿，逐项对照简历。修正遗漏、合并错位、旧申请遗留、错误日期、乱码、数字与标点变化，以及凭空产生的证书、技能、奖项或资格。
- 上传后检查教育、工作、项目、奖项及附件条目数量，不能因为解析看似成功就跳过核对。

## 字段映射与内容整理

- **教育/工作/项目**：名称、职责、日期、地点、学位等从对应条目取值；区分公司任职日期与具体项目日期。材料只有任职日期时，不自动当作项目起止时间。项目日期缺失且网站必填时，先查用户已允许的材料，再最小确认，不编造月份。
- **粒度与枚举**：按控件实际支持的年、年月或日期选择；只有年份的获奖控件无需额外询问月份。先选可能触发联动的日期、至今选项及奖项类别，再填其他字段，并重查是否被清空。
- **时间控件必须实际选择**：打开日期选择器，通过框架定位并点击实际年/月/日单元或用computer use点击；范围控件分别完成起止选择，年份与月份控件按实际粒度选择。“至今”使用对应真实选项。不得直接写input.value、移除readonly或仅派发input/change事件代替选择；日期文本已显示仍可能没有组件绑定值，导致提交报“未填写”。
- **时间核验**：逐项记录原始事实、当前显示、实际选择动作与选择后结果；检查组件选中态/绑定值、起止顺序、至今是否禁用结束字段，以及安全的失焦/组件校验提示。原有日期错误即使有文本也须重选；不能只修报红的一个字段，也不能以最终提交测试校验。
- **项目说明**：保留产品面向的用户、需求/痛点、本人职责、产品设计、方案选型、技术链路和成果之间的因果关系；根据对应项目组织完整句子。关键词、核心数字和用户确认的上下文不能在压缩时丢失，不堆砌“xx/xx”。
- **字数限制**：先读实际限制和计数方式。能容纳时使用获准材料的完整内容；超长时删重复或次要修饰、合并同义内容，以完整语句缩写。不得按字符直接截尾；核对关键内容与数字后再填。
- **奖项/证书/语言与技能**：按简历拆成实际独立条目，核对名称、等级、年份与说明；不能把不同奖项并进一个说明框，也不能沿用解析生成的虚假资格。
- **AI协作/作品与链接**：从相应已确认项目抽取任务、本人贡献、设计与结果；按用户要求保留或排除具体内容。网站链接使用真实域名或URL，开源链接与上线作品按字段用途填写，不以“项目网站”标签替代域名。
- **声明与必填空项**：身份、资格、承诺和同意项依据材料、用户答复及当前授权处理。用户指定自己填写的字段保留给用户，同时继续其他字段；其余确实缺失且影响投递的事实只做最小确认，不让用户重新整理整份简历。

## 填写、保存与读回

1. 检查实际页面控件及当前值；保留本次范围外的用户修改，避免整表覆盖。
2. 用页面支持的交互填入字段，正确触发输入、选择、失焦或保存；采用程序化填写时同样触发组件所需事件。不能把DOM临时值视为组件或服务端已保存。
3. 条目填写后读回显示文本、选择值、日期、计数、空项和错误提示；字段联动或重渲染后再次检查。需要确认保存持久化时，先确认草稿保存成功再安全切换/重开，并核对内容，避免丢失用户未保存修改。
4. 检查全表必填字段、条目数量、附件、链接和同意状态。只使用明确的保存/草稿或安全预览控件，不用最终提交按钮试探缺项。
5. 截图前激活实际目标页并等待绘制，核对截图与当前读回一致。保存可供用户审阅的完整字段内容、来源、附件文件名与Hash、缺项和脱敏截图；审核包中的必要申请内容保持私有，认证秘密不进入审核包。

## 返回用户审核

把完整表单及材料整理成有版本或Hash的私有审核包，标明当前公司/岗位、完整已填内容、来源、实际保存状态、未填项、账号规则和最终按钮。提交后会撤回、替换或影响既有志愿的，明确对应后果。

回到父Skill的Review阶段，按具体岗位与审核版本取得最终投递批准后才进入Submit。后续修改实质内容或附件时更新审核版本，不沿用旧批准。
