# 投递登录处理

由Agent完成已授权的登录页面操作、条款阅读与勾选、验证码填写及登录状态检查。支持手机号验证码、邮箱验证码和微信登录；用户指定方式时优先使用该方式。只在实际缺少输入或需要用户本人确认时请求最小必要参与。

## 入口与会话检查

1. 从父Skill读取当前公司、岗位、准备授权、用户指定登录方式及私有账号配置。保留用户已登录的Chrome或指定浏览器会话。
2. 核对招聘官网及其实际跳转的认证平台。先检查页面账号标识、个人中心和目标表单；已登录就继续准备，不重新发验证码或切换账号。
3. 页面仍加载时等待账号与表单状态稳定。用当前页面与账户信息判断，不能把“网页加载完成”当作登录完成，也不能把空白加载态当作用户没有资料。
4. 需要登录时由Agent点击正确入口、选择方式并执行允许的页面操作。优先使用目的明确的浏览器工具；遇到真实失败后，再按项目登记顺序切换computer use或内部浏览器。保留目标页与审核页。

## 手机号验证码登录

- 从用户指定的投递简历、私有配置或明确回复读取完整手机号，核对国家/地区码和当前账号。掩码号码不能用于推断完整号码；材料冲突时只确认具体差异。
- Agent填写号码、阅读登录相关条款、操作允许的验证控件并请求验证码。记录发送/倒计时状态，不记录号码或验证码原文。
- 已明确授权读取验证码的渠道可用于获取当前公司、当前登录请求对应的新代码。没有可访问渠道时，只请求用户提供这次验证码；其余页面操作仍由Agent完成。
- 填写代码并提交登录。过期、错误或未送达时，先读取实际错误和重发条件，再重新获取当前请求的代码；不反复盲点发送、不套用其他网站或旧请求的代码。

## 邮箱验证码登录

- 从同样的获准材料读取邮箱，核对表单发送目标与账号。Agent完成邮箱填写、条款操作及验证码请求。
- 使用用户已经授权的邮箱连接器或已登录邮箱页面，限定查找本次招聘登录的发件方、主题和时间。若读取授权或渠道缺失，只询问必要的授权或当前验证码。
- 核对邮件对应本次账号、公司与请求；区分验证码和验证链接，采用网站实际支持的方式完成验证。过期或出现错误时依页面提示处理，不把邮件送达当作登录成功。

## 微信登录

- 由Agent选择微信入口，检查实际弹出的授权页、二维码或桌面微信确认界面。用户已登录微信时，先尝试当前浏览器/微信支持的授权确认流程，不把打开登录页交回用户。
- 已授权且工具允许的桌面微信确认按钮由Agent操作。若当前流程要求用户在本人手机上扫码、确认或完成生物识别，只请求这一步，随后由Agent继续等待回跳并检查账号。
- 检查窗口关闭、回跳URL、页面账号和目标表单。二维码出现、微信窗口打开或授权页关闭都不能单独证明招聘账号已经登录。
- 平台要求创建账号、绑定手机号/邮箱或合并已有账号时，先检查实际提示与用户已确认的账号关系；超出当前授权的绑定或合并另行确认，避免改动历史投递所在账号。

## 验证、隐私与交接

- 按实际工具和平台规则处理验证码与CAPTCHA。正常交互可以继续；遇到明确工具限制或本人确认要求时请求最小动作，不能换路径绕过该限制。
- 密码、验证码、Cookie、会话令牌、二维码和身份材料只用于当前认证步骤，不写入日志、审核包、测试样例、Skill或GitHub；截图应避开或遮盖这些内容。保持浏览器登录状态，不导出凭据。
- 返回私有记录：公司/目标页、登录方式、已登录/待代码/待本人确认/实际失败状态、脱敏证据位置、尚需动作。凭当前账号标识及可访问的目标表单确认登录；必要时从个人中心再读回。
- 登录完成后回到父Skill检查账号投递历史、名额、冷冻期、刷新和志愿顺序，再调用内容填写子Skill。登录操作不包含最终投递、撤回或替换历史申请。
