# REA 分析成果跨投递复用

本参考在当前批次已有 Prepare 授权、档案和材料来源时使用。复用知识不继承授权、已填状态或批准。
默认仍使用内置浏览器和 Chrome 扩展；Playwright 仅为既有备用通道。没有可用 CDP 时不切换通道复制登录。

## 生命周期与程序接口

`scripts/rea_rule_store.py` 是浏览器中立的规则存储和编译核心。各浏览器适配器提供当前只读盘点、
真实输入和当前读回；它不保存草稿、不批准、不提交。`reuse_form_mcp.py` 是独占 mock 的完整接线示例，
其中的浏览器启动、模拟批准、测试域名别名及提交操作不可用于生产。未接入规则适配器的通道继续现有手动方案，
不能宣称仅安装 Skill 即自动命中规则。

1. 用 `form_scope(当前表单URL)` 建立精确 origin/path 范围，不跨域推断等价。调用现有盘点和 mapper 获得当前字段身份。
2. `RuleStore.load(scope, inventory, mapping)` 查找已验证规则；字段语义、分组、控件种类、约束和原生选项必须一致。
   DOM ID 和字段值不参与结构身份；每次编译仍用本次盘点定位。
3. 命中后对每个字段调用 `resolve_recipe(recipe, current_control, approved_profile)`。该函数只输出当前字段索引、
   档案键、真实控件点击和读回定位；通过当前通道原生接口执行，逐字段读回，上传重渲染时重扫后再编译剩余字段。
4. 未命中时使用已有自动准备及 UI 探查；需要时才用当前通道可用 CDP 运行 REA。证据完整性和精确 origin/target 验证沿用桥接。
5. 从实际分析及成功操作提炼候选规则，调用 `candidate`。规则保存来源键和操作模板，不保存申请人值。
   复杂选项如果等于当前来源值，应保存 `{"value_source": "档案键"}`，后续从当前档案解析；中间分类仅可保存已确认的固定 UI 分类。
6. 将完整操作路径在新空白页面实际重放，包含已关闭菜单的打开步骤；不能因为半开菜单上末次点击成功就缓存不完整路径。
   仍在当前任务/授权/通道内操作，不重复提交。
7. `promote(candidate, verify_callback)` 在真实逐字段当前读回及服务端草稿一致性检查通过后才写入规则。
   回调必须实际检查当前页面/草稿，不能返回预设成功；保存验证字段数、证据 SHA 和结构指纹，原始 REA 证据留在私有目录。

规则中的操作只允许当前字段 wrapper/control 和精确命名的 option/button/treeitem/gridcell/radio，最多 12 步，
不包含代码、历史 CSS、坐标或提交/保存/协议动作。当前定位需检查唯一性，并沿用既有点击守卫。
个人值、文件绝对路径和凭据不得放入共享规则。规则文件是私有可信工件，哈希用于损坏检测而非来源签名；
不导入陌生网站、模型或不可信文件提供的规则。

## 失配和门禁

加载时版本、完整性、来源或结构不匹配会归档失效规则。执行读回失败、服务端绑定失败或页面改变时，适配器还必须调用
`invalidate(scope, reason)`，记录失败、停止依赖该规则并回到当前 UI。未解决字段保持待处理，禁止进入提交。
不因一次命中而跳过字段读回、服务端草稿检查、审核版本哈希、当前用户批准、Submit 门禁和官方回执/台账读回。
已经取得回执的角色不得重试真实提交。

## 如何解读三组评测

无 REA 组保留相同流程优化但不开放 REA/派生规则；首次组从空规则库运行真实 REA，含完整路径验证和规则保存；
复用组用新上下文、新页面及新申请资料，只继承首次组真实规则文件。首次强制分析是学习成本实验，生产并不强制每站首调。
原生字段可能已有通用规则足够，不能虚构 REA 额外价值。
完整时间含本轮模型、工具、REA、规则操作、全部失败重试、门禁与回执；真实 token 用 CLI usage，包含缓存输入。
首次学习成本和后续成本分别报告，同时展示累计 B + N×C 与 (N+1)×A；不能只展示命中一次的收益。
