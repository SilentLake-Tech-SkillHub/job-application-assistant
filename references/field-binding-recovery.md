# 显示已填但表单仍判空：定位与恢复

当输入框显示内容，失焦、下一步或保存草稿仍报必填错误时，必须加载本策略。先排查字段定位、控件类型和联动重置，再判断输入事件是否被页面接受。截图只说明可见现象，不能证明根因或服务端保存成功。

## 先确定填到了哪个字段

重新读取当前页面。把“所属条目 → 字段标签 → 实际控件 → 关联错误”对应起来，逐一核对姓、名、电话等邻近字段；同一父容器中的首个input不能代表整个容器内的每个字段。重复教育/工作条目先定位条目，再定位字段。

优先使用实际关联label、可访问名称与唯一id。`data-automation-id`可作辅助证据，但必须核对当前作用域内的匹配数量、真实标签及控件类型；平台名称或属性稳定不代表唯一。结构位置仅在已逐项核对映射后使用，重渲染后重新检查。只读盘点发现共享容器或字段身份不明确时，必须人工式核对UI后才能填写。

读取该字段自己的`aria-invalid`、`aria-describedby`/`aria-errormessage`和可见错误；容器含多个字段时不能把第一条错误传播给全部字段。错误消失只是本次校验线索，仍须验证取值与保存。下拉中的搜索词不是选中值，日期文本也不能替代实际日期选择。

## 三种操作通道

| 通道 | 操作与恢复策略 | 核验依据 |
|---|---|---|
| 内置浏览器 | 用当前工具提供的页面快照和定位/输入动作；确认唯一可编辑文本控件后聚焦、清空、填写并安全失焦。若该工具支持逐字键盘输入且页面存在键盘处理，再换这种方式。下拉、日期、级联打开并选真实选项。工具没有某API时不能臆造；必要时按已授权范围切换可用通道。 | 操作后获取新快照，逐字段核对真实取值、标签、选中项和该字段错误；联动后重查。不能只依据动作返回“成功”。 |
| computer use | 用最新截图和可用辅助功能信息确认窗口、字段标签、位置及焦点。点击准确控件后，只在该控件内全选并重新输入；输入动作或粘贴未被接受且工具支持按键时，按页面所需键盘交互重填。点击安全中性区域或已确认的下一字段失焦，避免Enter触发表单提交。滚动、弹窗、布局变化后重取截图。 | 逐字段观察完整显示、实际选中项及就近错误；可横向核对姓/名防止错位。坐标、OCR与截图不能证明后台保存。安全保存草稿后重开读回才报告持久化。 |
| Playwright | 在获准使用的页面/会话中用精确作用域及`getByLabel`/`getByRole`定位；先检查`count() === 1`、可见、可编辑。文本默认`fill()`；确认键盘处理需求后，清空再`pressSequentially()`，避免追加。安全失焦并使用条件断言等重渲染；原生select用`selectOption()`，自定义选项通过UI点击。 | 文本`inputValue()`/`toHaveValue()`、选择控件选中项、该字段关联错误分别核对。对重复匹配不盲用`first()`/`nth()`。草稿保存确认后安全重开，重新定位并核对；不以最终提交测试。 |

通道切换只改变交互手段，不能扩大岗位/内容/提交授权，也不能绕过管理策略拒绝。只对已有授权且有明确故障证据的字段恢复，保留用户在其他字段的改动。

## 证据分层与停止条件

1. **显示值**：目标控件实际可见/读回内容正确；另核对邻近字段，防止覆盖错位。
2. **页面接受**：实际选中状态、该字段校验反馈及联动后取值正常。没有红字或`aria-invalid`缺失不能单独证明已绑定。
3. **草稿持久化**：明确的保存确认后，在不会丢失未保存修改的前提下切换或重开，内容仍正确。没有安全草稿入口时，记录“显示已核对，持久化未验证”。
4. **最终投递**：另走审核版本与具体岗位批准，并以回执证明；前三层不代表提交。

每次恢复记录字段、输入来源版本、原现象、定位证据、操作通道、方法变化和各层结果。相同方法出现相同失败时，不无限重试；只有新的定位/控件/键盘证据才支持下一次尝试。仍失败则保留页面与缺口，继续可独立处理的授权字段，并明确阻塞项。不得改`input.value`、移除readonly、改组件内部状态或派发事件来伪造完成。

## 截图案例中的技术结论如何使用

“编辑器命令重填后报错消失”只能是某次页面的观察，不能推出`execCommand('insertText')`普遍产生可信input或修复所有受控组件。该API已弃用，是否触发input/beforeinput取决于浏览器和配置，不作为默认恢复策略。`isTrusted`也不能证明字段身份正确、应用状态更新或后台保存。只读DOM诊断和隔离测试可使用页面脚本，真实填写仍使用工具支持的交互动作。
