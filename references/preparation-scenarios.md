# 登录与内容填写维护场景

维护父Skill或两个子Skill时逐项审查以下场景，并把结果保存在工作区的私有验证记录。示例只用虚构或脱敏输入。场景审查验证指令的可执行性与一致性，现场登录、保存和投递另以真实页面证据记录。

| 场景 | 输入/现状 | 预期处理与检查依据 |
|---|---|---|
| 已登录账号 | 目标浏览器已有账号与可访问表单 | 复用会话，读回账号及历史，不重新发验证码 |
| 手机号登录 | 本批次已开启 login-phone-otp；手机号在投递简历中 | Agent填号码、请求短信，结果默认用户提供/输入；完整接手需三次确认、具体短信来源授权及平台允许；图形验证单独走 captcha-solve |
| 邮箱登录 | 已授权读取本次登录邮件 | 只查对应发件方、主题与时间，区分验证码/验证链接，回跳后读回账号 |
| 微信登录 | 本批次已开启 login-wechat；桌面微信已登录 | 不自动点快捷确认或 OAuth允许；三次确认后仅按平台允许范围发截图到已核验私密渠道，用户本人操作，Agent核验回跳 |
| 过期或受限验证 | 错误代码、过期页面、人机验证或工具明确限制 | 读实际错误和重发条件；不盲点、不复用旧码；图形默认用户完成，已确认接手也不得绕过平台或风控限制 |
| 默认材料来源 | 指定短版简历，另有旧表单和已验收长版 | 默认只用指定简历及用户明确更正，不能自行扩写或沿用旧表单 |
| 用户要求扩写 | 用户允许用已验收长版补项目；字段有空间 | 从指定版本取完整内容并标来源，最新版确认事实处理冲突 |
| 日期与联动 | 项目未给日期、任职日期明确；奖项控件只有年份 | 不把任职时间冒充项目时间；仅问真正必填缺项，先填联动类型后核对其他值 |
| 解析污染 | 上传后生成不存在的证书并漏掉奖项 | 先完成上传解析，再对照简历修正虚构项及遗漏，核对条目数量 |
| 内容超长 | 字段限制比项目说明短 | 按完整语句压缩重复描述，保留痛点、职责、方案关键词与成果，不直接截尾 |
| 读回失效 | 临时DOM值正确但重渲染清空；截图仍是旧页 | 核对唯一字段定位，使用支持的输入/选择动作、安全失焦并重查实际值；激活目标页等待绘制，截图和读回一致才记为已填 |
| 用户自填与提交 | 用户保留一个字段自填，其他内容已准备 | 继续其他字段，标记缺项，返回完整审核包；无对应最终批准不提交 |

| 日期显示但未绑定 | input有日期文本，组件值为空并报“未填写” | 实际打开选择器并点击年/月/日；重选所有同类时间控件，核对组件绑定/选中态、至今和失焦校验；禁止直接赋值或点最终提交试错 |

每次检查还需确认公开包不含个人简历、真实账号、验证码、Cookie、私有路径或实际投递数据；项目端与公开副本逐文件Hash一致。


## 自动化子Skill授权

| 场景 | 输入/现状 | 预期处理 |
|---|---|---|
| 未授权 | 批次没有自动化授权记录，页面要求手机登录 | 不调用 login-phone-otp；请用户本人登录，其他准备工作继续 |
| 含糊同意 | 用户说“继续”“你看着办”或只批准投递某岗位 | 视为未开启；需要时再问一次 Query |
| 半自动 | 只批准 login-phone-otp 与 terms-consent；页面出现微信登录和家庭住址栏 | Agent请求短信，用户默认提供码；条款按逐项或三次确认后的本次代勾处理；微信和家庭住址交给用户 |
| 全自动 | 5项全部批准 | 不自动等于三次确认；普通验证点击由Agent做，短信结果/图形默认用户完成，微信本人授权；已确认接手仅在平台允许范围执行，证件号及最终目标审核门禁不变 |
| 短信未到 | 已完成三次接手确认、指定短信来源授权且平台允许，等待超过约1分钟 | 查页面发送状态，最多重发一次，仍无则请用户看手机；不复用或保存旧码 |
| 平台禁止代填验证码 | 执行Agent政策不允许输入验证码 | 只请用户输入这一码，其余步骤仍由Agent完成 |
| 微信未登录 | 页面只有二维码 | 三次确认后按平台允许范围发最少截图到已核验私密渠道；用户扫码/操作，完成后核对账号；不得转发的认证材料留在原页面 |
| 人机验证默认 | 获取短信时弹出滑块，未完成接手三次确认 | 说明类型与用户动作，交用户完成；普通点击不等于图形接手；反复出现则暂停该网站 |
| 人机验证接手 | 用户明确要求完整接手，三次确认完成且平台允许 | 在确认范围用受支持computer use处理图形挑战，最多2次，核验结果；失败交用户，不绕过安全限制 |
| 证件号必填 | 个人信息栏缺身份证号导致其他栏无法保存 | 其余字段填好不刷新，请用户本人填写并保存后继续；读回时不复述证件号 |
| 缺失隐私信息 | 简历没有家庭住址 | 列出缺失项向用户索取，不推断 |
| 条款与最终按钮 | 已选本次全部代勾并完成三次确认，真实性承诺资料已确认 | 已覆盖普通承诺直接勾选，不逐项重复问；“确认投递/我已知晓（不可修改）”仍需完整目标与当前审核版本批准 |
| 具体新协议 | 全部代勾后遇到需要明确接受、此前未披露的新协议 | 提供协议名称、链接及必要后果，取得对该协议的接受后再操作；不以三次确认替代 |
| 持续权限与本人步骤 | 全部代勾后出现OAuth新增权限或本人身份操作 | 持续权限仍按平台逐次确认，微信允许及必须本人步骤交用户，不靠责任声明越界 |
| 撤销授权 | 用户中途说“短信别读了” | 更新记录，之后改为请用户输入验证码 |

## 连续推进与通道切换

| 场景 | 输入/现状 | 预期处理 |
|---|---|---|
| 桌面微信授权窗口 | 微信已出现「允许」窗口 | Agent不点允许，也不切系统脚本代点；三次确认后按平台允许的私密截图流程交用户本人操作 |
| 通道缺失 | computer-use 未启用、终端无辅助功能权限 | Query 预检时告知启用路径；流程中先用其他通道兜底 |
| 平台限制提前声明 | 执行 Agent 不处理某类步骤 | Query 时一次说明并给替代安排，不在流程中途首次提出 |
| 交接前做到最后一步 | 手机登录需验证码 | 已填号码、按已确认模式处理条款、点获取短信后交接；截图避开验证码，用户提供/输入这一码 |
| 交接集中 | 两家公司各有一个待用户处理的步骤 | 继续其他公司，最后合并为一条交接消息 |
| 目标确认集中 | 一家公司投 3 个志愿 | 按公司汇总成一张清单一次确认，不逐个打断 |

## 批量登录与逐家推进

| 场景 | 输入/现状 | 预期处理 |
|---|---|---|
| 批次开站 | Query 确定 6 家公司 | 一次开 6 个标签页，各推进到登录交接前最后一步，一条消息列出全部登录动作 |
| 登录期间 | 用户正在登录 B、C 两家 | Agent 推进已登录的 A 家：读规则、上传附件、填写并保存 |
| 决策集中 | A 家需选志愿与部门，且缺紧急联系人 | 汇总为一次提问，答复后一次填完 |
| 表单保护 | 填写 A 家时需要查资料 | 另开标签页并显式 tabId，不导航表单页 |
| 无草稿站点 | 站点只有取消/投递 | 先问完全部决定再一次填完 |

## 全表控件与下拉伪填

- 下拉组件内部input显示某个奖项名称，但未选中枚举，页面仍报未填写：盘点应分类为select；必须打开真实选项并选择，不能继续给input赋值。
- 搜索文本与选中项分别核验；级联更换上级后重查下级，奖项更换类别后重查名称控件是否变为文本或另一组枚举。
- 原始枚举无真实奖项时只用官网实际其他/自定义入口；不存在入口则按用户明确指示处理。删除后重新定位剩余条目。
- 脚本不读取control.value并过滤所识别的认证输入，但label、placeholder等元数据可能含个人内容；`valuesIncluded:false`不是无个人数据保证。输出仅用于本次授权求职且不擅自分享；动态控件、未渲染步骤和未知只读控件继续UI检查。合成测试通过不代表官网保存通过。

显示已填但仍报错、共享容器字段错位或联动丢值时，必须按[字段绑定恢复策略](field-binding-recovery.md)逐项恢复并记录分层证据。
