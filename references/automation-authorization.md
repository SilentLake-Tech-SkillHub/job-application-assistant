# 自动化授权：Query、模式与记录

五个自动化子Skill默认关闭。它们处理的是登录凭据、短信、人机验证、个人隐私和法律条款，任何一项被误用都会直接影响用户账号或留下错误承诺，因此每一项都要先由用户明确开启，才能在本批次调用。

| 子Skill | 处理内容 | 永久边界（任何模式都不变） |
|---|---|---|
| [login-phone-otp](../skills/login-phone-otp/SKILL.md) | 填手机号、获取验证码、按授权读取短信并填写 | 只用本次请求的新码；平台禁止代填时由用户输入 |
| [login-wechat](../skills/login-wechat/SKILL.md) | 选择微信登录，点击本机微信快捷确认 | 手机扫码、生物识别由用户本人完成 |
| [captcha-handoff](../skills/captcha-handoff/SKILL.md) | 截图识别人机验证类型并交接 | 不自动破解或代为通过 CAPTCHA |
| [privacy-info-fill](../skills/privacy-info-fill/SKILL.md) | 电话、邮箱、地址等个人信息填写 | 证件号码由用户本人填写；缺失信息向用户索取 |
| [terms-consent](../skills/terms-consent/SKILL.md) | 阅读并勾选登录/隐私/真实性/须知类条款 | 不点击最终投递或“确认投递” |

## Query

在批次 Query 阶段、任何登录或填写动作之前，问一次：

> 本轮是否开启自动化子Skill？可选：①不开启（全部由你本人操作）②半自动：只开启其中几项（请列出）③全自动：5项全部开启。各项含义与边界见上表。

- 没有回答、回答含糊（如“你看着办”“继续”）或只批准了别的事项（如批准投递某岗位）时，按“不开启”处理。批准投递不等于开启自动化子Skill。
- 用户只说“全自动”时，逐项列出将开启的5项和各自边界，请用户确认一次。
- 用户可随时收回或追加某一项；以最新的明确指令为准，并更新记录。
- 授权只对当前批次有效。新批次、新的公司范围或换了执行Agent时重新 Query，不沿用旧批次。

## 模式

- **未开启**：子Skill不调用。Agent只完成不涉及上述内容的工作，到登录、验证码、个人信息、条款处停下，请用户本人操作后继续。
- **半自动**：只调用已批准的子Skill；未批准的步骤交给用户。例如只批准“手机验证码登录”和“条款勾选”，那么遇到微信登录、CAPTCHA、个人信息时仍请用户处理。
- **全自动**：5项全部开启，但上表右列的永久边界不变。

两种模式都不改变父Skill的最终投递门禁：每个岗位仍需用户按审核版本单独批准才可提交。

## 记录

在私有批次记录（不进入公开Skill、Issue或截图）写入：

```json
{
  "automation_mode": "off | semi | full",
  "approved_subskills": ["login-phone-otp", "terms-consent"],
  "approval_ref": "时间 + 用户原话摘要",
  "sms_read_allowed": true,
  "revocations": []
}
```

每个子Skill开始前读取这条记录；记录里没有自己的名称就不执行，直接把该步骤交还父Skill并说明需要用户本人完成或重新授权。
