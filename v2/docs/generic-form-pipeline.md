# 通用页面建库、映射与连续填写

公司名、岗位ID、个人答案只进入私有数据。共享代码按控件语义和页面框架执行；禁止为单家公司编写临时模板生成器、硬编码字段编号或按数组顺序猜日期配对。

## 首次建库或结构变化

1. 保留已确认岗位、原页面和账号。内部建库调用 `capture_rea_structure`，显式传入原 `pageId`、`pageUrl` 与建库授权。REA 仅被动观察当前宿主已有目标，不启动或切换浏览器。宿主无此能力时返回 `REA_HOST_CAPABILITY_REQUIRED`，不能改用另一个浏览器冒充原页。
2. 该入口在原页面一次归集 CDP DOMSnapshot（定位属性、父子关系、backendNodeId、布局矩形）、原生 AX 树、已加载脚本来源和 REA 脚本正文，再执行同页控件规范化。完整数据保存在同一固定私有结构资产中，只向模型返回计数、Hash和缺口。多个表单分别识别，标签允许中间包装层；Ant 清单与普通 DOM 清单交叉去重，附件和表单外输入不能消失。两次观测必须同目标、同页面且相邻。REA 的 AX 节点编号不是 CSS 选择器；有歧义的结构必须通过实际浏览器控件确认。未对应的交互节点保留在 `uncorrelatedControls`，在建库中逐项关联到实际选择器，或有依据地说明它是表单外导航/重复无障碍节点。不能静默丢弃。
3. 用 `form_mapping_candidates` 读已有原子事实候选；需要业务定义线索时，用 `form_script_search` 在已捕获的私有脚本中查字段、校验及依赖，不把整份脚本塞进模型。候选是提示，不是已完成映射；同名学校、经历、起止日期必须带栏目、记录和控件语义确认，再调用 `profile_map_questions`。在个人主档已有的答案不得再问用户。
4. 对选择器、选项、条件和重复栏目做增量采集。`capture_choice_options` 的证据绑定本次 capture；搜索结果、当前可见结果和完整菜单分别标记。日期精度、上传网站回显、学校/专业联动必须有真实控件证据。
5. 用 `form_build_template` 生成统一模板，必须绑定本次 REA 的 `structureId`。普通文本、原生选择/日期、Ant、UD 和经典飞书使用共享驱动。尚不支持的控件、未采到的选项、未确定的映射都返回 `blockers`，不会被改成 `userOnly` 或用“待补充”伪装为选项。模板草案保存于私有运行目录固定键并覆盖更新。
6. `form_build_template` 默认只返回缺口、计数及 `draftId/draftHash`，完整模板留在固定私有草稿；无建库缺口后直接用该引用 `template_register({companyId,draftId,draftHash}) → probe_conditions → template_finalize`。注册会重新核对公司归属、模板Hash及缺口，禁止模型把大模板读出后再次抄回。需要诊断整份模板时才指定 `compact:false`。生成模板不等于现场验证完成，REA 证据也不等于填写成功。

## 已建库公司的复用

正常填写复用已经封存的资产，不再调用 REA。`form_route` 判断需重建时只补缺失/变化部分。`form_template_audit` 可检查旧模板中被错误标为 userOnly 的普通字段，归还给建库阶段，不伪造旧资产已通过。

## 岗位材料与业务必填

岗位材料来自正向评审确认的批次 `roles[].materials`，保留主表行链接、列、原文及主数据Hash；公司配置和个人事实不另存材料值。搜索端组批及确认负责完整传递，申请适配器、队列及所有准备/读回入口读取同一来源，缺少材料契约的旧批次不得执行。

`business-materials.mjs` 是通用规则入口，`role-material-context.mjs` 核对公司、岗位和原站点。推荐码字段按已观察的题目/placeholder语义映射到 `material:referralCode`；它不是个人主档缺失事实。网站必填属性保持原值；当已确认岗位有适用代码时，冻结计划计算 `effectiveRequired=true`。漏字段、漏映射、错误来源、未激活分支、普通 userOnly 或留空均阻断，部分填写授权不能放行。没有代码和代码待核实分别记录，后者属于 Agent 材料工作。

冻结输入包含完整材料契约及确认摘要。材料变化使旧计划失效；独立读回再次从原确认岗位解析材料，并精确核对原始代码，空白、尾部空格、网站错误提示都不能通过。完成报告的 `materialCoverage` 必须完整且对应本岗位材料Hash；公司完成与提交结果记录均检查这一证明。

旧批次只补材料时，由搜索固定脚本预览 `amend-materials`，附用户授权原话及原批次摘要执行；不改变岗位、顺序或批次ID。申请端调用 `company_batch_refresh_materials` 验证材料补充确认与岗位集合完全相同，保留任务ID、原页面、登录及已填内容，撤销旧计划/完成核验引用，返回新队列Hash。不能通过重新组批或重新开页完成迁移。

## 连续执行与停点

`workflow_advance` 对已确认队列中的不同公司执行完整准备和独立读回；每次仍检查原账号、岗位、材料与冻结计划。每家公司传当前顺位的一个岗位，不能越过公司内部的志愿顺序。共用招聘域名的公司串行、独立域名并发，避免争抢同一账号资源。一个公司待用户输入不会停止其它公司。失败写入不会盲目重试，最终提交不在本工具中。

调用结果的 `continuation` 区分：

| state | 责任 | 后续 |
|---|---|---|
| construct / map / repair | Agent | 执行 nextTools，保留已完成字段，只处理缺口 |
| technical_block | Agent | 依据错误调查；证据或输入改变后再试，并推进其它公司 |
| user_input | 用户 | 只询问确实缺失事实或本人操作，其它公司继续 |
| review | 用户 | 完整字段读回通过，交用户核对 |

模型不得把 `needs_attention` 一律当作回合完成；先看责任类型。仍有 Agent 可处理工作时继续调用，不能要求用户反复回复“继续”。真实不可解决的技术阻塞需说明具体原因；不因追求不停顿而无限重试、臆造答案或绕过门禁。

已启用对话的 `PostToolUse` 保存固定的 continuation 路由，`Stop` 对同回合未处理的 Agent 步骤提醒续跑。尚有 Agent 待办时先阻断并要求执行下一工具；连续两次 Stop 之间没有新的已追踪MCP结果时，宿主登记 AGENT_NO_PROGRESS_LOOP（complete=false、owner=supervisor）并停止空转。新的真实工具结果重置计数；不能把这个监督交接冒充用户等待或完成。真实技术故障必须通过 `workflow_handoff` 引用已落盘 MCP 错误/驱动缺口，由组件核实后交给监督者；交接仍为未完成，不可写成审阅就绪。新回合、其它对话及有证据的用户等待按各自作用域处理。宿主必须加载对应事件，单元测试不代表驻留 DSH 已重载 Hook。

## 统计和独立核验

`summary.fields` 只统计字段，`summary.structure` 统计栏目/重复记录检查。`counts` 保留旧接口兼容性，禁止把其 match 总量说成已填写字段数。保存、提交、官网回执仍分别核实。

`userOnly` 只适用于验证码/认证秘密、敏感证件和协议签署等确需本人步骤。性别、学校、日期、普通附件不能因为驱动没接好而标成用户专属。直接编辑旧 JSON 不能使不完整资产变成可执行资产。

## REA 宿主接线

受控浏览器宿主通过已连接页面的 `Target.getTargetInfo` 获取真实 targetId，调用 REA 的 `inspect-web-page --include-script-sources`。允许来源从该页实际加载的 Script 资源树提取，覆盖已观察到的 CDN；不猜测来源或请求未加载模块。脚本正文、DOM属性与布局仅留在私有固定资产，脚本内容Hash与字节数会核验，结果报告已包含、已排除及限制；不能把策略过滤的采集宣称为网站所有脚本。命令只用参数数组，不使用 shell。默认使用本机缓存的 `rea-agents@6.7.0`；可用 `RECRUITING_REA_COMMAND` 指定已安装命令的 JSON argv 数组。存储键和控制台正文不采集，具有输出大小和时间上限。正常填写复用封存资产，不重复全量采集。DOM读取器按源码修改时间加载，修正标签/层级规则不需要重开浏览器。

REA 端点来自该宿主的 `RECRUITING_REA_ENDPOINT` 或既有 `RECRUITING_BROWSER_CDP_PORT`，只允许本机端点。没有端点就报配置缺口，不为取得端点重开浏览器。内置浏览器使用 `startHostBrowserBridge({reaInspect})` 注入宿主针对原 tab 的被动采集能力；未提供时明确阻塞。配置改动和代码测试均不证明驻留宿主已重载，需读取实际运行能力并现场核验。

## 强制存储与工具契约

每个字段的内容来源、控件类型、定位、依赖、完整动作与独立读回必须同时存在。采集即登记控件证据，构建即覆盖保存完整草案及主档 `companyForms.executionContract.fields`，包括阻塞项；注册后读回模板和主档并逐字段核对。缺动作、未知语义、把交互框当只读文本或普通 userOnly 都无法注册及封存。封存Hash绑定模板内容及实际条件探测回执；改模板后不能沿用旧证据。路由、预检、填写与完成记录逐层检查同一契约。

两个 MCP 的公共工具统一经 `registerWorkflowTool` 注册。新增工具必须声明自己是纯查询或哪个工作流阶段，否则启动失败；阶段工具统一返回 `workflowContract`、`continuation` 和 `completion`。Hook 对实际启用会话动态消费这些元数据，不依赖易遗漏的固定工具名单。DSH 中须由当前宿主调用作用域 enable 入口，启用后验证真实 PostToolUse/Stop；未启用的其它会话保持独立。

## 真实选项匹配和提交选择

`capture_choice_options` 先取真实候选并恢复页面。`form_resolve_choices` 对同一事实的已确认别名（学校中英文、缩写）以及主档明确批准的专业映射做精确规范化匹配；其它模糊结果只排序，Agent 必须给语义等价证据才可选择捕获列表中的实际选项。原始个人事实不改写，映射、选项Hash和搜索词覆盖保存在私有选择资产，构建时一起固化。来源或列表变化则旧映射失效。运行时搜索实际标签、点击唯一真实选项、失焦，再独立读已选状态；INPUT 的搜索文本本身永远不能作为选择完成证据。无对应选项时继续采集官网“其他/添加”分支，不能硬填不存在的学校或专业。

## 下拉框的代码验收链

实际规则在 MCP 代码中：`capture_choice_options` 读取本字段实际候选及 DOM 暴露的 value/id/disabled/selected；`choice-resolution.mjs` 对主档原值做别名或模糊候选排序并确认具体候选，保存原值、目标原文、实际值及采集绑定；构建和注册读取同一私有选项资产，拒绝无确认记录的别名映射。路由复用和冻结预检同样核验，不能手写模板 enumMap 绕过。

执行器只在当前绑定菜单内精确定位唯一候选，检查禁用和实际值，再点击、失焦和重新展开。`choice-proof.mjs` 必须读到该候选的实际 selected 状态；高亮/aria-activedescendant 或搜索框文字都不算选择。可用的实际 value 必须保持一致，临时 DOM id 只作观察证据，不能冒充业务 ID。

`choice-verification.mjs` 由 Engine 自动执行独立重展开核验。已显示同样文字的字段也须验证后才允许跳过；`verifier.mjs` 缺少该证明即失败，不依赖 Agent 是否读了 Skill。`inspect_choice` 可在未封存表单上对一个已捕获字段核验：分别读已选文字和搜索 input.value，返回候选实际选中状态、恢复结果及该字段截图；这是核验，不会更改已选答案。截图失败或缺少选中证据要明确报告未核实。表单保存和重新打开后的持久化仍须另行证明，不能拿界面选择证明冒充保存回执。

## 真实专业与申请专业

个人主档每段教育分别存 `education.<id>.major.zh`（完整真实专业）与 `education.<id>.major.application`（用户确认的申请备用专业），旧 `.major.canonical` 经 `preferRealMajorMappings` 迁移并移除，不再同时存第三份专业值。模板字段始终绑定真实专业；文本输入直接使用真实值。下拉有真实专业时强制优先，只有完整菜单已证明不存在或已搜索真实专业得到无匹配证据时，才允许用申请专业对应的真实选项。专业不是公司代码常量，选项不存在仍阻断。字典搜索的明确无结果状态返回可恢复的空搜索证据，不作为浏览器故障。原专业、备用专业或策略变化使旧选择确认失效，重新建库冻结；显示原专业文字不证明控件支持自由输入。

禁用下拉只在两次同页读回均证明实际禁用、已有选中标记和相同非空值时，记录 `captured_locked_value`，作为只能核验的锁定字段，不猜父依赖、不点击、不把空禁用框视为完成。正式读回强制再次核对禁用状态及原值。需要用户输入的敏感号码仍按敏感字段处理。日期结束字段只关联同一记录已存且有来源的 `.ongoing` 布尔事实，不能借用别段经历的状态。

对明确传入 `capture_choice_options.selectors` 的日期控件，采集实际日期面板的完整文本、标签与“至今”入口并恢复原值；有真实入口才能生成相应动作。网站必填结束日期、主档仍在做且完整面板确实没有“至今”入口时，`workflow_wait_for_user` 重新核对同页采集、映射、同一记录事实及恢复证据，登记具体表达决策后才允许停在用户输入。普通映射未完或无采集证据不能转成用户等待，也不把空结束日期推断为网站认可的至今。页面就绪只要求实际可见容器存在；操作与答案读回仍要求具体字段唯一，岗位身份仍独立核对。

用户明确批准网站使用经历截至日期时，个人主档只存一条有来源的网申日期事实，表单的 ongoingDateRepresentation 仅引用它并限定公司、岗位、完整页面URL及具体结束字段。date-representation.mjs 在建库、取值、冻结和独立读回应用该表达，真实项目ongoing及end事实保持原义。授权、日期或范围变化使旧冻结计划失效。已记录的有效决定不能再次转成用户缺资料。

日期范围只按同一真实日期组件内采集的两个输入建立 rangePeerSelector/rangeIndex；不得从整页数组猜配对。可复用模板不存另一端的个人日期，编译器从本次冻结的同框字段推导，任一端缺值、配对改变或起止倒置即拒绝。范围驱动点击实际日期单元格、核对两端显示、重新展开两端核对真实 range-start/range-end 标记。失败报告包含当前字段ID、来源及标签，不能用输入文字或单元格高亮替代范围已选证明。

范围核验导航到各端日期所在月份再读实际标记，导航本身不得选择或改值；原生可编辑范围允许键盘提交，但同样必须通过此证明。date-range-verification.mjs 在完整准备与独立核验入口统一执行，verifier.mjs 对缺少或不一致的dateRangeProof强制失败，不能因为文字原已一致而跳过整个完成门禁。章节标题统一为对象，Ant章节从本次采集的所有真实sectionSelector逐一读取，不能用一个form根的首个标题代替多个章节。

附件栏目标签排除已上传文件名及上传列表内标题。采集保存每个真实文件及唯一、可见的移除控件引用。用户明确指定移除某一文件时，form_remove_attachment 限定原队列、账号、页面、栏目及精确文件名；操作前重新核验，操作后独立两次读回剩余文件，保留其他附件。该操作不能进入普通模板或由通用click代替，回执不代表全表完成；空附件决定仍经本页面问题映射及个人主档登记。
