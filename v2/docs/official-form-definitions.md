# 官网完整表单定义

建库先检查公司是否已有可用资产。有则直接离线映射和冻结计划；资产缺失且私有公司目录存在已核实的 `<companyId>.definition.json` 时，`workflow_next` 首先返回 `capture_form_definition`。没有配方则保持可见控件和条件分支增量建库路径。

当前支持 Wecruit 模板 getter。配方绑定公司 origin、实际观察到的模板接口、官网前端代码来源及 Hash。请求仅发送当前岗位表单 URL 中的模板 ID 与语言，以官网实际使用的表单编码 POST 读取定义；接口不能指向简历编辑、投递或登录端点。随后只读取受限的官方选项字典 CDN。公司配方、返回定义与个人事实均不进入公开安装包。

工具保存完整定义、来源和 Hash，并将所有栏目、普通题目及条件题目强制登记个人 JSON。`isNeed=0` 为必填；条件字段从 `beRelationItems` 与真实选项编码共同解析。未知类型、找不到父选项或重复问题 ID 都返回错误，不能当作完整定义。

定义包含尚未展开的字段，但不证明控件已实测或表单已填完。仍须把定义和实际 DOM 对应、建立原子事实映射、核实控件驱动、冻结计划并独立读回。未覆盖的页面声明、附件、条件行为和重复条目需要继续核对，不能凭元数据 Hash 放行填写。

已获取完整定义的公司，执行模板必须绑定同一 `officialDefinitionHash`，且每个定义问题都有 `schemaQuestionId` 映射；缺少选填题或条件题也会阻断封存与资料编译。不能只完成可见控件后跳过空栏目。学校和专业的“使用原文作为答案”选项只有实际被捕获时才能建立 `optionTextMap`，不得映射到相似专业。

多个岗位 URL 若指向同一实际 `resumeId`，MCP 在任何浏览器写入之前拒绝并发写。这类站点须单页完成共享简历，确认保存后再刷新其他岗位进行独立核验；仅串行点击旧页签仍可能覆盖自动保存资料。不同公司的独立记录继续并发。

Ant 表单使用 `antq:` 栏目、题目和重复条目的逻辑引用。实际操作前在当前 DOM 一次性解析这些引用；层级路径仅用于当前操作，不作为持久公司定位器。共用路径的编辑器按真实岗位、模板查询参数区分，个人简历记录 ID 不参与问题身份。没有显示岗位标题的编辑器使用当前 URL 的实际岗位 ID，不能把预期标题伪装成页面读回。

用户操作的第三方登录通过公司资产声明 `loginMethod=user_operated`，在已观察的账号页核对有来源的准确账号标识；没有匹配账号时交给用户。不会转成手机号登录，不请求短信，也不交换浏览器登录态。
