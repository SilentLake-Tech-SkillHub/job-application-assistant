# 维护端规则

本文件约束维护宿主（`RECRUITING_HOST_ROLE=maintainer`）如何根据执行端的失败修复共享代码。执行宿主只调 MCP，维护宿主只修代码、调只读检查；两者分工见 SKILL 与 [对话级 Hook](conversation-hooks.md)。

## 1. 先聚合，再修复

动手前运行 `node scripts/failure-summary.mjs --private-dir <私有运行目录>`（可加 `--since <ISO时间>` 只看本轮）。它把落盘的核验失败和 MCP 错误按“失败码 × 控件类型”跨公司聚合，列出涉及公司、题目标签样例和证据 runId，不输出填写值。

- 一次修一类：先修出现次数多、涉及公司多的类别；同一类在不同公司的现场合并为一个 Issue、一次修复。
- 只修单一现场的补丁必须说明为什么它不属于任何已有类别。
- 每个修复在 Issue 里写清楚覆盖的失败码、控件类型和证据 runId。

输出末尾还列出“返回量最大的调用”：两个 MCP 对每个公司/任务 × 工具累计调用次数、耗时和返回字节（私有目录 `metrics/`，每项一条、覆盖写，不含参数或填写值）。返回字节就是进入模型上下文的量，用来定位 token 主要花在哪个公司、哪个阶段。宿主侧的实际 token 计数在宿主日志里，MCP 看不到。

## 2. 先复现，再修复

能用已落盘证据（控件采集、REA 结构、核验 checks）在测试里复现的失败，先写一个失败的测试，修复后让它通过，再交执行端真机复测。真机复测仍然必须做（代码测试不证明驻留宿主已重载），这一步只用来减少真机回路次数。无法离线复现的交互（例如日历动画、异步候选）在 Issue 里写明原因，并说明真机复测要看的证据。

## 3. 门禁变更先做影响评估

任何收紧门禁、改变冻结/封存 Hash 构成、改变模板或计划契约的改动，合并前在 Issue 里列出：

- 哪些已封存模板、冻结计划、核验报告会因此失效（用 `form_assets_status`、`form_template_audit` 和私有 templates 目录核对）；
- 失效资产的迁移方式（重新采集、重新封存或一次性迁移脚本），以及执行端要重跑的范围；
- 能否只让受影响的字段/驱动失效，而不是整张表。

没有这份评估的门禁收紧不合并。一次性迁移写成独立脚本，执行后删除，git 留回滚点；不在主流程里保留兼容口子。

## 4. 新框架适配器准入

新的招聘框架（或现有框架的新控件）只能以可复用框架适配器进入：在 `shared/control-registry.mjs` 声明控件类型、动作、读回与模板可用性；在共享操作模块增加执行分支；附带覆盖重复/隐藏元素、相同选项文本、未提交值、动态新增控件和 RPC 路径的测试。禁止按公司名分派，禁止写死域名。

## 5. 止损记录的处理

执行端同一失败出现两次会被止损（`STOP_LOSS_REPEATED_FAILURE`，记录在私有目录 `stop-loss/`）。维护端修复并让执行宿主重载后，代码版本指纹变化，止损自动解除；不要手工删除止损记录来放行未修复的调用。

## 6. 就绪检查（三个时点强制运行）

`node scripts/readiness.mjs --workspace <工作区> [--host-config <宿主 MCP 配置>]` 只读，按 个人数据 → 批次 → 公司资产（入口能否认出岗位、定位稳定性、表单模板能否执行、记录归属、栏目放置）→ 运行态（本批队列）→ 宿主接线 逐层检查，对批次里每家公司给出“可执行 / 不可执行 / 已处理”及原因。

必须在三个时点运行，并把结果附在 Issue 或交接里：
1. 门禁或契约变更合并前：结果里新出现的“不可执行”就是这次变更的影响面，必须写明迁移方式后才能合并。
2. 批次内容变化后（补材料、改链接、改顺序）：确认执行端队列已接续，没有失效队列被继续使用。
3. 执行宿主开工前：宿主缺 REA 端点、交接目录或角色配置时不开跑。

栏目放置与“记录内非本记录字段”目前只报告、不拦截；改为拦截前，先把现有模板的报告结果交用户确认并完成迁移。

## 7. 学会新的点击目标

执行端交接的失败码以 `_ACTION_TARGET_REQUIRED` 结尾时，不改驱动代码，先走“报告 → 用户确认 → 写入组件”：`scripts/learned-targets.mjs show` 生成给用户看的候选清单，用户确认后 `add` 写入 `catalog/learned-targets.json` 并提交。只有同类失败在多家公司反复出现、需要新的执行逻辑时，才改驱动代码。细节见 [通用控件合集](control-collection.md)。
