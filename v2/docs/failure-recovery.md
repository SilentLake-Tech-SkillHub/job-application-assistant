# 浏览器失败恢复与诊断

## 问题与处理边界

暂时性错误计入失败、宿主丢失错误类别，属于同一类恢复问题。失败记录只保存最新状态，不建立副本。提交、短信请求、验证码提交及任意填写动作不使用自动重试，未知提交结果仍禁止重试。

`stop-loss.mjs` 不拦截任何调用：同一真实失败出现两次时返回 `ask_user`，把失败字段和证据交给用户，其他公司继续。

超时、页面关闭、导航中断和断连分别返回明确错误码，不计入失败次数；无法分类的通用运行异常也不冒充确定性错误。安全可重入的读取、打开岗位和声明式入口，在组件内部最多尝试三次，间隔 250ms、750ms。恢复只重连原配置的本机专用端点，或重开已绑定页面的原有 HTTPS 地址，不切浏览器通道、不接管日常 Chrome、不创建第二个资料目录。元素缺失不盲重试，返回重新采集入口并预览确认的提示。

`browser-errors.mjs` 保留错误类别、操作步骤和去敏定位/定位 Hash；`broker-diagnostics.mjs` 记录去敏原始消息和栈。凭证类消息整体遮盖；数字、邮箱、URL 查询及引号内内容不原样落盘。错误详情继续通过闭合字段清单校验；含访问器或多余字段的原始诊断整体拒绝，不执行其 getter。

批量定位报错可能携带一整组引用；不能用列表开头的附件定位推断“附件失败”，也不能把记录消失一律归为再次上传。应比较前后完整控件和原生 DOM，确定缺失的具体栏目与记录，并核对真实执行阶段是否发生过上传。

网站可能收回新增后始终空白的重复记录。完整模板已封存、事实和岗位已冻结时，先用既有 `role_prepare_fields` 填写该记录的已知普通命名锚点，再立即重新盘点记录数及完整控件；不得绕过采集链或岗位账号守卫。确认新记录稳定后，按整表只读核验的真实差异分批续填，不反复执行扩空行、重建、整表准备的循环。该步骤不清止损、不重传附件、不猜日期，也不把局部写入当成全表通过。若守卫拒绝或记录仍消失，保存真实证据继续定位，不擅自取消履历覆盖要求。

局部续填运行同时保存其完整冻结计划引用。最终提交仍须用户对具体岗位/模板的提交授权、当前整表独立核验通过、字段与授权证件来源未变；之后可由同岗位、同页面、同模板的真实成功局部运行及其内容 Hash 正确的完整计划核对附件，避免仅因旧整表运行引用缺失而再次上传。局部运行本身不认证整表完成，未完计划、未知答案、失败运行、旧模板/其它岗位或附件变化仍拒绝。旧局部运行无计划引用时，不补造记录；用当前计划正常核对一项已知普通字段并重新整表核验。

## 已有资产影响与迁移

- 不改变模板结构、封存 Hash、冻结计划格式和最终提交授权；不向模板添加敏感字段动作或号码。
- 证件与条款勾选框的归属由 `business-authorization.mjs` 按主档单一开关统一决定（见[持久业务授权](generic-form-pipeline.md#持久业务授权)）；既有 `userOnly` 敏感标记保留，新待办和状态在读取时按当前开关重新分类。开关改为 0 立即生效：执行端重新编译计划，这些项转为本人操作，无需改写旧模板。
- 主档中证件号缺少来源或引用了不存在的来源时，保留原资料并报告为本人处理，不中断整份状态报告。证件号始终不进入普通资料解析和计划值；普通字段的来源校验仍保持严格。已有合法冻结计划不受影响，携带证件号原文的异常计划被拒绝，须按授权路径重新生成。
- 原有模板和计划仍受实际采集/映射/封存校验。代码换版不等于控件定义变化，不主动重建仍有效的资产；只有实际契约或采集证据校验失败才重新采集。不伪造旧回执，也不批量清理其它公司的记录。执行宿主只对当前用户授权范围重新建库、封存和核验。
- 同一站点新旧映射中已经失活且不要求覆盖的问题，不再计为缺答案或本人待办。
- 新旧定位比较时，仅旧 Phoenix 问题允许返回“当前不存在”；没有对应节点就不生成等价证明。当前模板的控件仍严格解析，未知、格式损坏和类型改变仍拒绝。问题迁移继续要求本岗位当前模板的完整已恢复探测证明；只按已有唯一事实替代或现场等价条件退休旧映射，未证明的条件问题与所有事实值保留。此修复不改模板/计划结构，不修改事实或手工清止损。
- 按实际变更模块确定重载范围并读回驻留版本：MCP 流程/元数据改动只重载执行服务，控件驱动或主控改动再重载对应 broker。浏览器未改动时保留其页面与活体选中证明，不能为追求全源码摘要相同而反复断开。单元测试不能代替真实页面验证；重新运行 `scripts/readiness.mjs`，未封存或未核验的岗位仍不报告可投递。
- 保留浏览器的主控换版须先保留实际持有浏览器的进程；若退出旧的无用主控，必须等它完全退出、Unix socket 清理完成后再发布新 socket。Node 服务关闭会按启动时的路径清理 socket，不能在旧进程仍退出中时把新 socket 换到那个路径，否则会出现新进程还活着、入口却消失、MCP 启动拒绝的接线故障。MCP 接口缺失时先核对启动日志和 socket 实际健康，不重复要求用户登录。

## 验证

截图遮盖按实际框架的问题标签及证件类型前缀识别，Phoenix 与原有 Ant/UD/ATS 使用同一规则；只读标签/属性，不读取敏感号码。证件号控件的 name/placeholder 可能只有通用字样，不能因此漏遮。含长数字的 DOM id 不作为返回选择器，避免把可能的号码写进截图定位元数据。截图源码变更后必须核对真实截图及遮盖数量；旧未遮盖稿不再作为审阅证据。

附件验收恢复统一见[通用流程](generic-form-pipeline.md#附件截图与模型验收)。旧下载字节证明不作为验收，重新核验该岗位即可；未保存字段和已上传文件保留，不重传来制造一次“新成功”。

官网字数约束属于完成门禁。原生 maxlength/tooLong、Phoenix 实际可见的字符计数器超过上限，以及字段内可见的错误提示，都进入独立读回 errors；主档与页面文字相等不能覆盖它们。该观察规则不改模板/计划结构、不写页面；部署后当前申请必须重新整表核验和视觉复核，旧 verified 报告不能代替新检查。不截断原事实；受限题使用有来源的正式简历表述时，仅通过主档与映射工具登记并重新封存该契约。

普通准备调用不构成替换已有附件的授权。官网已明确回显上传成功的附件保持原样，最终按当前文件卡和截图模型规则独立核验；不匹配仍 needs_attention，不能因为保留就判通过。已有文件状态不明时拒绝覆盖；确需移除或替换必须走原有逐文件授权接口。只有实际新增上传才触发解析后的重采/修正阶段，不能把重复准备误作每次重新上传。本地源版本以元数据核对，用户授权继续继承，现有附件和页面保留，无事实迁移。

上传解析会改变记录条数及控件类型。恢复顺序为：保留成功附件 → 按确认材料核对并补齐重复记录 → 重新采集控件/选项 → 建库封存 → 只读整表核验 → 按真实差异分批续填，不能把首次失败处当成全部剩余字段。`role_restage_autocomplete` 专门解决非空自动完成框既无被动候选、又无法在完整模板封存前重建的循环：它是有明确授权的准备写操作，原只读检查仍不清空已有值；内核从已捕获普通字段及有来源主档冻结计划，前后核对岗位/账号/页面和事实 Hash，当前值须与主档或其已知别名一致。先登记尝试，只清该框，再双次证明空值且无旧实体，要求重新采集、冻结后填写。不接受敏感/未知/禁用/只读字段，不进普通模板，不重传附件，不自动重试或宣称原选择已恢复；失败保持 needs_attention。已有完整模板与计划格式不变，新代码回执仍按现有规则重新采集，两家仅恢复当前受影响控件；事实与未保存页面保留。

`test/failure-recovery.test.mjs` 覆盖同状态拦截、组件实际观察到变化后恢复、Agent 自述无效、真实本机 RPC 观察、有限退避和非幂等动作不重试。`test/authorized-profile-classification.test.mjs` 与原有授权测试覆盖草稿、主档状态、执行计划、撤回和例外，号码不出主档。宿主错误透传、脱敏和访问器拒绝由原有 RPC 集成测试继续覆盖。
