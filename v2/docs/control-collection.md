# 通用控件合集

唯一能力定义是 `shared/control-registry.mjs`：控件类型、输入值类型、动作方法、读回类型及模板是否允许使用。`runtime_info.controlCapabilities` 返回同一注册表。公司资产只提供题目映射、已采集选择器、选项和证据，不注册公司专用执行代码。

## 数据流

- 采集与独立读回共用 `control-dom.mjs` 的可见性和唯一匹配规则；原有 inventoryDOM / observeDOM 导出保持兼容。Ant / 飞书的语义解析仍在各自通用适配器。
- 模板接收入口先统一语义引用的原文/URL编码表示；模板检查、离线编译消费同一控件合同。全页位置定位仍不能封存为正式模板。
- PageAdapter 的所有动作进入 `control-operations.mjs`；RPC 将同一动作发送给所选通道，不在客户端另写 UD 或日期处理。宿主 bridge 仅转换 SDK 参数，不重定向框架点击。
- 文本、原生选择、复选和单选操作后限时等待控件提交并读回实际值；等待只读取、不重复写入或点击。选项及日期等完整语义仍由 Engine 的独立读回验证。操作成功、模板封存、保存及提交为不同结果。

## 定位与执行规则

1. 优先问题 ID / 属性与重复条目局部锚点。无命名布尔输入向祖先查找稳定问题属性或语义类；排除样式哈希、状态类和单纯控件库外观类。找不到可靠锚点保留诊断定位，禁止封存。
2. 多个候选时只接受唯一可见目标；first 不可放宽唯一性检查。样式化的原生布尔控件允许由其可见 label 证明可操作。
3. UD、ARIA、Ant 下拉使用同一个选择流程：题目 → 实际触发器 → aria-controls / aria-owns 指定的菜单，或唯一可见菜单 → 精确唯一选项 → 失焦 → 独立读回。存在多个可见菜单直接拒绝；隐藏旧菜单不计入当前选项。
4. 采集不改变答案，关闭菜单并核对原值；失败不得宣称采集已恢复。
5. 日期保留原精度和至今语义，不生成未知月日；Ant 只读日期仍用真实面板操作并核对原输入。
6. 上传核对本地文件 Hash；只选择文件不算官网上传成功，必须读到官网附件行和已上传状态。网站把附件改名显示时，才需要取回当前附件比对原文件 Hash；取回入口只在该附件自己那一行里找，且必须唯一：先找名为“下载 / download”的控件，再看文件名本身是否为 https 链接，最后才用框架适配器（北森为下载图标）。链接用页面登录态直接请求，不点击。重复经历添加保持单次增加一条的检查。附件执行沿用采集时记录的框架类型，避免采集与执行使用不同控件合同。
7. 身份、敏感字段、验证码、协议及最终提交门禁继续有效。roleSnapshot 从实际 URL 返回岗位身份，不复制期望值。

## 页面信号的稳定性

识别页面（找元素、判状态）只能依据：业务事实（取回的文件内容、回执、接口结果）、语义（文字、aria、data 属性、输入值、组件库公开类名如 `ant-`、`phoenix-`、`form-item__`）、以及以它们为锚点的相对结构。网站打包生成的样式类名（如 `sc-xxxx`、`__sc-xxxx`、`___xxxxx`、`css-xxxxx`）和带内容哈希的脚本文件名每次重新打包都会变，不得作为判定依据。

- 登录与入口配置（`entry` 的标题、就绪、入口按钮定位，`account.selector`）：由 `shared/selector-stability.mjs` 判断，采集日期（`evidence.capturedAt`）在 2026-10-26 及之后的不合规配置拒绝加载；更早的仍可运行，由就绪检查列出并安排重新采集。
- 组件代码：`test/engine-page-signals.test.mjs` 扫描 `shared/`、`login/`、`scripts/`、`hooks/`、`application/`，出现上述信号测试即失败。框架专用识别写进框架适配器，用公开类名、相对结构和组件自带图标等，不写进打包产物。

## 找不到点击目标时：报告 → 用户确认 → 写入组件

驱动在一题或一行里找不到唯一的点击目标时（错误码以 `_ACTION_TARGET_REQUIRED` 结尾），不猜、不点整行，而是把这一行可点的元素列进错误细节（`driver_target_gap`：标签、角色、组件库公开类名、相对这一行的结构定位；不含文字和打包生成的样式名）。流程：

1. 执行端照常停在该字段，按驱动缺口交接给维护端，不自行换点法。
2. 维护端运行 `node scripts/learned-targets.mjs show --run <runId> --private-dir <私有运行目录>`，把 `show_user` 原样给用户看。
3. 用户确认用哪一个后，维护端运行 `add --candidate <序号> --quote "<用户原话>"`（只有维护宿主能写），写入 `catalog/learned-targets.json` 并提交组件。
4. 执行端重载后在原页面重跑。驱动先用内置点法，找不到再按顺序试已学会的点法；每次点击后仍必须通过原有核验（右侧已选正好是目标、重新打开读回一致），不通过就取消并恢复，不会填错值。

已学会的点法对所有公司的同类控件生效。目前接入：北森双栏列表（`phoenix_list_popup.selection`）与北森地区面板（`phoenix_area.selection`）。新驱动接入时在 `shared/learned-targets.mjs` 的 `DRIVERS` 登记，并在驱动里用 `resolveTarget`。错误的点法用 `remove --id <lt-...>` 删除。

## 扩展与验收

文本控件可在已采集动作中明确声明 inputMode=keyboard，通过真实键盘事件输入；仍必须通过即时及独立读回，不把输入方式变更当作填写成功。

新增类型先在注册表声明合同，在共享操作模块增加执行分支；复用统一定位、菜单与读回策略。框架差异进入可复用框架适配器，禁止按公司名分派。测试至少覆盖重复/隐藏元素、相同选项文本、未提交值、样式化输入、动态新增控件及 RPC 路径。运行 `node --test test/*.test.mjs`，再对真实宿主页面验收；脚本通过不能证明实际宿主已重载。
