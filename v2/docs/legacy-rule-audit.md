# 旧版与 V2 规则审计清单

## 没有单独子 Skill 名称、但也没有被 MCP 全部替代的父规则

- **公司方案与资格**：已选岗位来自确认过的同版JSON；完整JD、适用计划、职责/资格、数量/共享/冷冻期等不能由填表成功推断。新版入口消费上游已确认JSON；Excel转换/同步校验已按用户要求剔除，实时账号名额与历史仍需网站证据。
- **用户选择**：岗位/公司顺序、意向部门/城市/调剂是具体目标选择；档案偏好不自动成为新授权。不重复问已有有效确认。
- **审核与最终提交**：填写完成、草稿持久化、内容审核、提交批准、确切目标确认、最终点击、回执是独立状态。V2当前没有最终提交工具；完整宿主PreToolUse安装、Review/Submit门禁接线尚未完成；固定结果事件入账与Excel/JSON同步已由 application_closeout 实现，真实官网回执判断仍须证据核实。
- **页面与恢复**：保护用户页及未保存工作；不重复申请；结果不确定先查历史；保留成功/失败证据。当前单岗位路由已保护原标签，十页窗口分组和全批关闭管理尚未在V2自动实现。
- **源资料/安全**：事实来源、材料Hash、用户更正优先、不编造、秘密不落盘、公开包隐私扫描继续有效。新用户导入尚缺；不把本人的已解析主档当所有用户已可用。
- **执行通道**：旧版默认IAB+用户Chrome双通道及备用切换已被本轮“独立Chrome+双MCP”取代；REA只用于内部建库。旧版“填写后断连接”不沿用，broker继续存活。旧版图形验证码接手改为人工。旧版把个人事实留在Markdown的实现改用私有JSON。

用户可逐行决定：保留为独立Skill / 合并到主Skill / 完全交代码 / 当前移除。审计决定前不擅自删除现有旧Skill。

## 用户最新接口边界

本套新版仅消费上游已确认的公司方案JSON；Excel→JSON、Excel同步及校验不在新版Skill/MCP职责内，相关适配脚本、Python依赖和测试专用输入分支已剔除。旧版规则里的Excel内容在本表仅作为历史审计项，不作为新版入口条件。
