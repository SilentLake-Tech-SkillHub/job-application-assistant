## 2026-11-05：公司编码统一与一次性迁移（2.0.0-alpha.8）

回滚代码基线：`e68d22b`。用户要求只用公司编码定位、共享资产复用，并授权推进全部任务、把真实投递验收放到最后。旧记录查 Git。

- 公司目录、任务归属、主档表单和存储资产统一用公司编码；不再分配 F 编码或读取站点/岗位到模板的第二层绑定。
- 配置文件明确保存所属公司编码；公司展示名称变化不使配置脱离，也不按共享招聘域名借用别家公司配置。原站点信息仍作为来源值保留，不自行修改主表选择。
- 公司模板保存共享控件结构，确认岗位提供本次标题及身份；独立核验仍拒绝错误岗位。回传按公司和岗位核对。
- 一次性迁移检查全部已绑定资产的状态及实际编译结果；个人事实、来源、用户设置、队列顺序和原页面编号保持不变。没有主表状态变更。
- 写入前要求执行会话暂停、检查源文件未被并发修改；在工作区外保存一次性恢复记录，逐文件读回。主档写入失败会回滚已创建的文件。旧证据文件不在本步删除，清理另经清单确认。
- 测试工作区的临时交接目录在测试结束时自动清理。

验证：全套 Node 907 项通过；随后补充秒级执行登记拦截和显式回滚测试，迁移专用 7 项通过。迁移专用测试涵盖个人事实保留、辅助观察继承、归属冲突、成功读回、真实文件权限错误回滚及执行中禁止迁移。

真实数据预检：18 份表单归入 15 家公司；8 份已绑定模板、15 条绑定岗位资产状态前后不变；5 个已选岗位的字段计数和阻塞项完全一致。24 份配置只转换所属公司编码，入口和登录路径不变。

状态：源码及预检完成；数据迁移、安装、驻留重载和最后的真实网页验收分别登记在工作区唯一任务单，不以离线测试代替完成。

## 2026-11-05：重复栏目、材料映射、计划存储与 Agent 注册（2.0.0-alpha.9）

- 编译时从主档获取已映射栏目的记录数量。优先使用已声明的实体列表，旧主档的其他记录类别从事实键读取。新增项目按自身来源取值，派生工作项目保留与所属经历的对应关系。
- 飞书、Ant 与现有 Phoenix 路径共用补条目流程。只学习当前页面中与记录容器绑定的唯一添加按钮，每次点击后核对只增加一条，歧义或按钮缺失时保留待处理状态。
- 同一来源问题下互斥的推荐码栏仅校验当前分支；无可执行分支仍报阻塞。一次性迁移只把已捕获的员工内推问题指向已确认岗位材料，原事实、栏目和封存状态保留。
- 计划以确认批次与岗位的固定任务身份落盘，当前输入相同时保留同一引用，不同工具复用同一槽。变化后的计划需重新冻结；独立材料暂存及正式核验凭据仍独立保存。
- 注册使用固定流水号、稳定实例键和独立／多 Agent 模式，同一实例跨会话编号不变。每个实例安装自己的 MCP 配置，禁止覆盖其他实例的配置，已部署角色沿用原值。支持为未收录宿主生成标准 stdio 配置，其内置浏览器不会自动视为可用。
- 影响范围：现有封存模板无需重新采集。新增条目改变相应岗位的计划字段，新的计划引用不可代替此前已经冻结的引用。旧的运行证据保留到逐项清理确认；既有会话不强行改编号。浏览器动作只在最后的现场验收中调用。

验证以工作区唯一任务单记录的测试和真实运行结果为准。
