# 当前修复记录

## 2026-11-11 · 2.0.0-alpha.61

本轮按用户要求收敛现有修复分支并发布主线；统一锁文件与组件版本为 alpha.61。旧账号核对页及独立封存修复仅以 Git 合并记录保留回滚，现行实现不变。发布验证包括完整离线回归、公共资产检查、源码与分发逐文件核对，以及公开主线 CI；公司现场验收继续独立记录。

用户授权按四步流程修复首次建库及已有公司缺口，并以两个原岗位完成生产验收。回滚基线 `7631e3c`。

- 每公司唯一视觉一级清单，同页 REA 与实时 DOM 交叉采集；一级通过后展开并补采子控件，沿用原一级对照，内容映射与独立核验继续执行。
- 共享实现覆盖空栏目入口、搜索输入与实体选中证明、原生单选标签、日期范围辅助输入、下拉关闭与状态恢复、附件卡片及只读内容读回。
- 空栏目展开归属检查使用可见栏目容器包含真实输入；隐藏的文件输入与可见文本一起登记为子控件，不因文件输入隐藏而漏掉。
- 公司表已声明条件关系且父控件已在一级表时，当前真实子控件按定位、标签、类型及页面归属进入二级。分支选中与读回仍由后续真实操作测试验收；结构归属不依赖一次探测是否成功。已完成语义映射的保留字段移除对应旧映射诊断。
- 补采只包含已证明展开的子控件、且同页一级身份一致时，保留独立一级验收引用；已操作消失的入口由实际展开回执接续，真实新增一级问题继续进入完整对照。展开回执保留原入口供模板复用。
- 已明确语义映射的题目不被仅按“推荐码”等标签的材料猜测覆盖，未映射材料题仍走原主表材料链。
- 条件分支探测在原分支内比较新旧定位是否指向同一真实输入；已恢复探测的同控件别名回补到调用表，继承已有语义并移除旧重复定义，随后重新实测；未证明别名的字段继续回补。
- 未展开重复记录的来源同样读取公司最新明确映射，按命名记录同步进行中状态，避免保留旧槽位来源。
- 当前草稿真实交互的每次实时控件登记与映射检查使用该草稿合同；正式填写仍使用正式合同。避免旧正式档案阻断已回补的新字段，草稿Hash变化仍拒绝。
- 原生文件输入通过同记录命名id定位时，与同记录普通字段一起按主档扩展和移动，不再把后续记录附件当成新问题。
- 重复栏目保留尚未展开的记录定义；只对存在真实添加契约、同栏目同来源字段且定位与动作一致的已观察列复用结构，普通缺失字段仍需补采。实际交互按主档选择展开和核验全部使用的记录，明确排除的记录保留定义并记录计划依据。
- 重采继承旧档案时，尚未显示的普通重复记录列沿用本次已观察的统一结构，保留各自命名来源及条件，不借用其他记录内容。
- 材料输入完成后先通过只读入口核对官网实际附件；未匹配时返回当前卡片和去掉查询参数的网络时序，沿用原页诊断，不把文件输入成功当成官网更新成功。
- 已有附件卡片不再依赖空状态的“上传简历”提示识别：同时核对采集与实时文件题目、简历标签、同一容器和唯一输入归属，再使用已批准文件。
- 公司模板调用及原封存契约沿用；既有正式模板、冻结计划和核验报告无需格式迁移。就绪检查前后只出现时间差，未新增不可执行公司。
- 离线回归和原岗位现场结果分别记录在唯一任务单；未取得两家公司独立核验前保持生产验收未完成。两岗均不提交。

- 建库、交互入口和档案确认检查主档显式记录在可展开栏目的覆盖，复用用户栏目放置规则，缺整类记录或同一记录重复绑定均回内容映射；作品栏目不再误识别为工作栏目。公司调用方式和已完成资产复用保持原样。
- 单选检查读取当前原生及渲染标记，上传检查补充经过脱敏的浏览器网络错误码，用于区分驱动和页面请求失败。

- 复合单选通过当前可见标签操作；ATSX原生选中与外层选中标记同时一致才验收，避免只改变原生输入而未提交到组件。网络错误码完整保留HTTP2等数字部分。

- 一级接续只约束原一级对应项；重复展开导致二级定位从单个输入变成行内定位时，按当前真实父栏目重新登记，不将二级定位变化升级成一级缺失。

- 空下拉的已选值节点尚不存在时，按实际控件清单判断控件在页并执行选择；最终仍要求独立读回，缺控件与缺已选值分别处理。
- 已有HTTP2上传失败、原页仍为旧附件且无活动上传时，允许明确的协议恢复调用。仅转发同来源、已观察失败资源的下一次原生上传请求，经HTTP/1.1请求路径接回页面，记录一次尝试并移除拦截；不重启浏览器，仍核验官网卡片。
