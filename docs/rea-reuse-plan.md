# REA 验证规则跨投递复用：实施与评测计划

规则核心、独占 mock 闭环和离线/浏览器拒绝测试已经实现；三组真实模型测试正在运行，结果尚未完成审计。
内置浏览器/Chrome 的实际通道接线仍由各自适配器提供，本次完整模型实测使用现有 Playwright 备用适配器。
现有实现和历史结果见 [REA 自动化设计](rea-automation-design.md)。

## 两条路线与当前证据

| 路线 | 已完成 | 尚未证明或实现 |
|---|---|---|
| 流程优化 | 指令去重、程序化语义映射/方案编译、普通字段填写读回、例外摘要、批量工具编排 | 单项优化的独立因果收益和真实 ATS 的长期效果 |
| REA 诊断与知识复用 | 按需真实 REA capture、私有证据及有界片段；新增验证规则核心、跨工作区复用及失效回退，独占 mock 接线通过浏览器检查 | 三组真实模型消耗/时间结论、生产各通道接线与真实 ATS 验证 |

历史 20 回合中，优化流程的 10 次投递只有 1 次实际调用 REA；其余 9 次未使用这次调用返回的证据。
warm 语义缓存由单独的本地原生字段预热生成，并非 cold 回合的 REA 分析产物。
原流程与优化流程合计对比为 4,702,154 → 2,386,165 token、1,387.41 → 645.29 秒；
49.3% 和 53.5% 的降幅属于整个流程组合，不能称为 REA 跨投递复用的收益。

## 目标闭环

1. 新网站或规则未命中时，盘点当前表单，先运行已有自动填写；仅在需要诊断时读取 REA 证据。
2. 依据真实证据产生候选规则，经当前页面实际填写、逐字段读回及服务端草稿一致性检查后才提升为可复用规则。
3. 下一次独立投递加载规则，核对网站范围、页面结构和字段语义，用当前档案及当前定位重新编译动作。
4. 每次都执行真实填写、当前读回、审核版本和提交门禁；旧规则不承载已填写、已批准或已提交状态。
5. 结构变化、歧义或读回失败时停止使用失效规则，回退到当前 UI 探查，必要时重新调用 REA；不盲目重试提交。

同站不同岗位和已确认等价的同模板页面可复用；跨域或结构不一致不能仅凭相似标题继承规则。
实际浏览器分工保持内置浏览器、Chrome 扩展及 Playwright 备用通道；规则核心不绑定某个执行器。

## 规则内容和验证边界

持久记录应包含版本、精确适用网站范围、结构指纹、字段语义及分组、档案源引用、控件操作模板、
读回规则、REA 证据哈希和验证记录。规则必须来自实际分析及验证，不能从 mock 答案预置。

不保存申请人的实际字段值、文件私有路径、登录状态、旧 DOM 句柄、坐标、历史批准或回执作为新任务授权。
操作中的候选定位要在当前页面重新解析并核对唯一性和控件角色；文件引用从当前材料清单解析。
复杂控件的步骤必须说明动态部分如何由当前档案值生成，不能把上次选中的学校或日期写成固定答案。
REA 原始证据仍留在私有目录；公共报告只记录合成数据、度量和哈希。

缓存生命周期为候选、验证通过、可复用、失效。只完成捕获、只得到模型口头结论或仅有 DOM 值均不足以提升规则。
读回失败须使相应规则失效，并阻止当前提交，修复后重新验证；同一轮和跨轮命中都应记录来源和实际消费事件。

## 三组真实模型对照

使用相同 `gpt-5.6-sol / high`、5 类 mock、合成资料、可见指令预算及完成条件。
五类为双语原生字段、搜索下拉、日期级联、重复教育和上传后重渲染。
新结果独立于历史 cold/warm 数据，不混用历史消耗计算本次收益。

| 组别 | 执行条件 | 要回答的问题 |
|---|---|---|
| A：无 REA | 保留相同流程优化，禁用 REA 和 REA 派生规则，使用当前 UI 完成 | 流程优化本身的参照 |
| B：首次 REA 分析及验证 | 空规则库，明确执行首次分析实验，捕获真实 REA 证据，实际验证并持久化规则 | 一次学习的完整成本 |
| C：后续复用 | 新模型上下文、新工作区/页面，仅继承该网站 B 组实际产出的验证规则 | 后续投递实际能节省多少 |

三组共至少 15 个独立投递回合；C 组必须在对应 B 组成功持久化后执行。
B 组为了测量首次学习而明确要求 REA，报告应标注这一实验条件，不能冒充生产中的必要调用。
普通原生字段也允许得到“已有自动规则足够”的结果，不虚构逆向价值；C 组不强制禁用诊断，
出现真实变化时允许回退，并把额外 REA、错误和重试如实计入。生产仍按需诊断，不要求每站首次必调 REA。

C 组不得读取 B 组会话历史、填写完成状态、档案值或模型总结来冒充规则复用；
应改变合成申请数据或动态 DOM 标识，并核验用的是当前值，防止固定答案和陈旧定位带来虚假成功。
三组均执行相同读回、草稿一致性、Review/Submit、独立服务端回执及台账核验；人工批准仍显式模拟。

真实 token 使用 CLI 回合 usage，并与逐请求/独立会话累计核对；区分缓存输入、未缓存输入和输出，
总 token 为 input + output，避免把 cached input 或 reasoning 再加一次。
完整时间从模型进程启动至退出，包含指令加载、模型等待、REA、规则读写/匹配、浏览器操作、全部失败重试和门禁。
规则生成成本在 B 组完整呈现，C 组不重复计入已支付的学习成本；同时展示 B + N 次 C 的累计成本和盈亏平衡，
避免仅展示单次命中收益。每格一次只作观测，不声称统计显著性；缺测、失败和回退不剔除。
