- **完整时间：**从 CLI 进程启动到模型回合结束及进程退出，含读取 Skill/档案、初始化、模型/网络等待、程序/UI、REA（如触发）、所有重试、草稿 GET/当前 UI 读回、模拟批准、实际 mock 提交、服务端回执和 Excel 读回。

- **cold/warm：**指语义结构缓存无/有预热，模型上下文两者都全新。warm 先用真实原生输入及当前读回生成验证缓存，关闭预热页、丢弃已填方案后再做正式申请；不预置复杂控件配方、不做额外 AI 预热。主图完整时间包含预热；明细另外列出实测预热和扣除该区间的派生时间。原流程的 warm 为负对照，具备同样的缓存构建前提但应用阶段不能消费它。

- **真实 token：**CLI turn.completed、独立会话累计与逐请求相加核对。input 含 cached input，output 含 reasoning，总量只加 input + output。语义 cold/warm 不控制提供方模型缓存，不将总 token 比例换算为金额。REA 自身不调用 LLM，证据解读已计入整轮实际 usage。

- **逐站独立：**每格一个新 CLI/浏览器/工作区，只有一个批准的合成岗位；20 格全部独立，不均摊共享 token。图中每个网站的柱子是该网站这一完整回合，五格相加是五个独立回合，不是此前共享上下文的五站批次。

- **验收：**每格真实 Query/Prepare/Review/Submit/Closeout、当前字段读回、审核哈希、服务器回执、Excel 读回；完整必需 Markdown 正文逐字匹配实际模型可见输出，要求零截断。模型口头声称不作为事实或成功证据。

- **失败计数：**MCP 错误指工具抛错；业务失败返回另计正常响应中的方案/读回/草稿失败。两类失败和所有额外探查均留在真实 usage 和完整时间中，不用成功回执掩盖中途失败。

- **范围：**相同 gpt-5.6-sol/high，冻结原执行器/增强前 Skill 与优化实现，交替两种流程的执行先后。使用现有 Playwright 备用通道；默认内置浏览器/Chrome 扩展仍需独立测试。真实求职调研、登录/验证码、人工等待未测；审核批准明确模拟，草稿重开恢复未测。

- **解释限制：**每格仅一次，模型探索、提示词理解、重试和网络波动都会影响结果；冷/热差值不能单独归因于语义缓存，流程间差值不能单独归因于 REA。当前 mapper 即使命中缓存仍重新盘点、核对语义并验证方案，不预设 warm 必然更快。

## 行为观察

- 部分没有上传控件的页面中，原流程回合仍额外探查或尝试使用简历来源。共同提示词强调 upload-first 但没有显式写出‘仅在存在上传控件时’，模型对这一表述的理解影响了探索成本。所有尝试和拒绝均计入，未改写提示词或剔除慢回合；差值因此也包含提示词理解及模型行为，不能全归因于程序速度。
- 优化后部分回合在程序已返回全部字段读回、没有剩余例外时，模型仍调用空或重复的探查/例外阶段。门禁拒绝了无必要的探索，实际字段未重复填写，但额外模型往返仍计入本轮 usage 和耗时；当前执行还不是最少调用路径。
- 优化后原生页面的模型说明出现‘已上传简历/重扫解析结果’的描述，但工具证据只显示六个非上传字段。该口头描述不作为事实；实际上传数量为零，成功标准取当前字段读回、服务端回执、审核门禁和台账。
- 搜索下拉的优化后 cold 回合先把读回定位设为外层 #school-widget，产生实际读回失败后调用了一次 REA；随后改为 #school-search 并取得回执。REA 触发路径真实，但此处首先是读回定位不匹配，尚未证明逆向诊断不可替代；后续应优先核对读回控件，避免把这种定位错误一律归因于隐藏绑定。
